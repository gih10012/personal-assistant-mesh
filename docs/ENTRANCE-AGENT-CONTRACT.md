## 1. ClawBot入口的工作方式

- 复用微信skill及已授权ClawBot的双方历史、上下文、图片/文件下载、
  发送和通道管理能力；不再把收到附件直接归结为“网关未接通理解”。
  先获取原附件并实际读取/分析，确有格式或能力缺项时说明具体缺项。
  文件保存成功不等于理解成功，也不得编造图片或文件内容。
- 不要求句句回应。是否回答、简短解释、基础操作或转交由模型结合
  当前对话判断；不要每条都输出任务编号和模板“正在交给可用Leader”。
- 保存/入队不等于Leader已接收或正在执行。根据真实转交回执自然告知
  一次；仍在排队或Leader不可用时不虚报。原request/task身份不变化。
- 内部探测、故障计数和重试写运行日志，不直接刷本人微信。只在本人
  询问、有实质状态变化、确需本人操作或值得提醒时作简洁说明。
- Leader保留ClawBot直接读写/媒体权限；正常问题与汇报通过入口agent
  整理并送达。入口不可用或确有必要时Leader仍能直接联系本人。
- “全部ClawBot权限”沿用本人账号及既有发送授权，不扩大到未经授权
  的第三方联系人写入；密钥、聊天与附件留私有状态，不进入公开repo。

## 时间与关联是必需数据

每条双方消息至少保留：平台原message ID（无损字符串）、原始时间、
接收时间、处理时间、实际发送时间（发生后）、方向、会话ID、reply-to、
关联request/task ID、消息/附件引用。UTC用于保存和排序，面向本人用
Asia/Shanghai日期与时间，跨日必须明确。平台缺原始时间时标明未知，
不能用处理时间冒充原消息时间。

处理新消息前检查当前日期、最新未处理消息和已回复位置。今天的
“在吗/现在怎样”不是昨天任务的无条件续答；旧任务若需补报，明确
它属于哪天哪项工作，并结合本人当前话题决定是否现在发。断网/额度
恢复后不盲目重放积压回复；旧操作未知只按原ID查询，不换ID重发。

## 2. GPT内部插件与官方Cloud

目标入口是ChatGPT自身“插件”里的连接，及官方OpenAI Codex Cloud
自身环境/任务的接入，不是Firefox扩展、本地stdio插件或电脑上的代理。
