# 默认并行工作与续接

2026-10-14 本人明确要求：没有严格先后依赖的计划项默认多 agent 并行；
各自用 Git 分支/worktree 开发，验收后合并。不要把整个项目排成单线程。
额度或 Goal 中断造成子 agent 真正停止后，保留原工作，恢复时直接续接
原 agent，不再让本人重复要求继续。

## 执行规则

- 从原计划/43个协调任务派生可独立工作的叶任务，不改原ID/依赖。
  每个叶任务记录负责agent、分支、worktree、base、所有权、检查点和
  合并依赖；源码、研究、文档、测试和审查均可并行。
- 同文件的不同开发也可在独立worktree推进，集成者解决真实冲突；
  不让多个agent同时写main的同一工作区。协调GOAL/PLAN/TASKS由Root
  单写，各分支的功能文档/测试由自己的agent维护。
- GUI/账号交互、部署、迁移及同一生产状态的写操作只由一个运维
  负责人按依赖执行。只读诊断和无关源码开发不因此暂停。公开HTTPS/
  OAuth/本人权限缺项只卡对应支路，不卡整张任务图。
- 子agent提交自己的安全代码和检查回执，Root审查commit、合并、做
  风险相称集成核验后推送。分支绿色测试不等于已部署或真实业务完成。
- 当前协作工具有4个活跃槽位，通常Root＋3个专员；有槽位就启动
  就绪工作，完成/停止后续接或分配下一叶任务，而不是只开一次并行。
  这是本次执行容量，不是Mesh协议或未来节点数量上限。

## 中断与恢复

先核原agent状态和原进程/session/job handle。仍运行就观察原handle；
观察timeout/临时断口不代表停止，不为它另建重复任务。确已因额度、
连接或Goal中断停止时，沿用原agent线程、worktree/分支、原请求/操作
身份和检查点续接；必要时先完成当前原handle的对账。未知副作用只
观察，不能换ID重试；已有成果也不能因换模型/节点重新执行。

本人明确pause时所有Goal工作暂停；本人resume后继续原Goal/专员，
不reset目标、累计统计、连续Leader历史或43任务。额度不可用时保留
待恢复队列，不伪装完成、不启用未授权付费模型或新增账号/key。
