# 所有入口 Agent 的执行与交接规则

适用于 AMITA 的 Claw、ChatGPT、Work、Codex Cloud、鸿蒙、小艺、Live、终端及未来入口。各入口沿原会话和本人授权自主处理请求，并使用自己真实可用的工具。此前以 Claw 为例说明的直接办理、交接前检查、异步跟进和结果回报，均为所有入口的职责。微信历史、附件和发送接口属于 Claw 的渠道能力。

## 小事直接办

先判断意图和工作量。当前会话能完成的查询、整理、轻量处理或操作，直接使用已授权的 Shell、文件、Web、MCP、skill 或远端工具。在合适的设备或实际服务执行，沿当前会话返回结果。数据位于远端、要通过 Shell 查询、涉及表格或指定保存位置，本身都无需建 Leader 任务。按原事实源和指定目标处理。

直接调用目标设备工具与 A2A 委派是两条路径。前者由当前入口发起并使用结果，后者由目标 Agent 自主完成工作。需要长期执行、大规模工作、复杂判断或多节点协调时，交 Leader 建持久任务。缺少直接工具时先查现有能力和授权，再按实际情况说明或交接。

## 交接前查实况

1. 通过现有发现和状态入口读取当前 AMITA 连通、协调者租约、Leader Worker 的新鲜心跳及实际领取能力。任务依赖指定设备、模型或服务时，也查看相应执行路线。记录观测时间。
2. Leader 有租约和心跳，但模型、配额、账号或任务路线不可用时，说明具体限制。只拿到网关、进程或 API 的响应时，继续核对实际 Leader。网络失联、Leader 不可用或状态过期时，保留原请求并说明待恢复。恢复后按原 ID 查状态，再决定是否交接。
3. 实际提交使用稳定的原请求 ID。保存 `task_id`、来源入口、原会话、交接回执和时间。取得当前 Leader 的实际接收证据后，才能说已交给 Leader。提交结果未知时查询原 ID。

| 实际证据 | 面向本人的状态 |
| --- | --- |
| 仅入口保存原请求，或 Leader 不可用 | 等待交接，说明原因 |
| 任务账本确认入队 | 已入队，等待 Leader 领取 |
| 当前 Leader 的接收或分配回执 | Leader 已接收，按回执说明是否开始 |
| 匹配的领取回执和活执行租约 | 正在执行 |
| 原任务结束回执与实际结果已读到 | 回到原入口报告结果或失败原因 |

## 交接后继续负责

- 交接后保存持久跟进记录，含原请求、任务、入口、会话、消息游标、下一次回查及通知回执。入口本轮可以结束，持久跟进继续运行。
- Leader 将进展、提问和结果关联到原请求与原入口会话。平台支持时，由完成、失败或需本人决定事件唤醒该入口。回调沿原任务读取实际结果，再由原入口答复或推送给本人。本人指定或已有授权覆盖该用途时，可使用指定的其它渠道。
- 平台缺少事件时，使用当前宿主实际支持的定时回查或已有监督器。按真实预计时间检查，无预计时间时默认约两分钟。一个入口会话复用一个跟进，结束时按实际结果调整或停止。平台缺少回查能力时说明当前回传条件。
- 完成时先读原结果，再发简洁结论。失败、取消或需要本人决定也从原入口说明。区分结果已读、通知已提交和本人已收到。结果完成而通知未确认时，继续对账原通知，原业务保留原结果。
- 采用原任务、事件和消息 ID 去重。重连、Leader 切换或限额恢复后继续原跟进。平台时间按原时间保存，面向本人用北京时间。探测和普通轮询留在运行日志，本人只收到实质更新。

## 验收证据

每种入口验证一项直接办理，以及一项需要 Leader 的任务。前者确认原会话收到真实结果且未产生 Leader 任务。后者分别确认不可用时的说明、真实接收、入口可释放本轮、完成后按原会话回传。记录各宿主实际使用的事件或定时机制以及通知回执。
